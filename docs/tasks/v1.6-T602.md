# [v1.6-T602] — Demandes simultanées à l'IA locale

**Version** : 1.6.0 · **Statut** : `[x]` · **Dépend de** : v1.4 (relecture, synchronisation)

## Objectif
Plusieurs demandes à la fois à Ollama (traduction et relecture) pour mieux occuper la carte graphique.

## Périmètre
**Inclus** : Réglage « Demandes simultanées » (1 à 4, défaut 2) dans Moteurs ; un limiteur commun traduction + relecture ; les lots traduits en parallèle reçoivent comme contexte les répliques d'origine précédentes ; bouton « Mesurer sur ce PC » (1 puis 2 demandes sur 40 répliques d'exemple, choix du plus rapide), avec Annuler.

## Cas limites (avant de coder)
- Ollama réglé pour une seule demande à la fois → les demandes attendent leur tour, rien ne casse. Une demande échoue → les autres s'arrêtent proprement. Mesure sans modèle → message clair.

## Critères d'acceptation
- [x] Avec un faux Ollama qui traite 2 demandes à la fois, 2 lots en parallèle ≈ 2 fois plus rapides (mesuré) ; jamais plus de N demandes en même temps (vérifié)

---
## Compte rendu
- **Fait** : `limite.js` (`creerLimite`, `enParallele`), lots Ollama en parallèle (contexte d'origine si les précédents ne sont pas finis), limiteur commun traduction + relecture, réglage `ollama.parallele` (1–4, défaut 2), `moteurs:mesurerOllama` / `moteurs:annulerMesure` + événement `moteurs:mesure`.
- **Vérifié** : `tests/parallele.test.js` (jamais plus de N, 2 demandes ≈ 2× plus rapide sur faux Ollama, ordre gardé, contexte d'origine) ; e2e `v16.js` (mesure appliquée).
- **Écarts** : bug trouvé par le test et corrigé : un lot parallèle recevait un contexte « undefined » (`every()` saute les cases vides).
