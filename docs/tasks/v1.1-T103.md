# [v1.1-T103] — Glossaire

**Version** : 1.1.0 · **Statut** : `[ ]` · **Dépend de** : T102

## Objectif
Garder les noms propres intacts et traduire certains termes toujours de la même façon, avec les deux moteurs.

## Périmètre
**Inclus** : `services/glossaire.js` (fichier `glossaire.json`, format versionné) ; entrée = terme,
traduction (vide = ne jamais traduire), langue cible (toutes ou une), respect de la casse ;
correspondance par mot entier, la plus longue d'abord, insensible à la casse par défaut ; le terme
devient un marqueur `<g n="k"/>` que les moteurs gardent en place, remplacé ensuite par la traduction
choisie ; Ollama : réponse refusée si un marqueur manque (réessai) ; écran « Glossaire » (ajouter,
modifier, supprimer, rechercher, importer un .csv/.txt `terme;traduction`).
**Exclu** : glossaires DeepL côté serveur.

## Cas limites (avant de coder)
- Terme dans une balise (`<i>Jon</i>`) ou en début de dialogue (« - Jon ! ») → reconnu.
- Terme qui est un morceau de mot (« Ned » dans « Nedra ») → pas remplacé.
- Réplique faite uniquement d'un terme (« Winterfell. ») → aucun appel au moteur.
- Marqueur perdu par le moteur → réplique signalée « à vérifier » dans le bilan (jamais un nom qui disparaît sans le dire).
- Import : fichier vide, mal formé, 10 000 lignes, doublons → lignes valides ajoutées, bilan « X ajoutés, Y ignorés ».
- Glossaire corrompu sur le disque → sauvegardé à part (`.corrompu`), glossaire vide, message.
